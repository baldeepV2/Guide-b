Getting started

Overview

What the guide covers and the process from start to finish.

Form Builder linkhttps://lam-evaluation-config-ui.mfe.exxat.com

This guide describes how forms are created in the Exxat form builder. Two methods are covered: creating a new form, and duplicating a form that already exists in a university (tenant). The guide also introduces the editor that opens once a form has been created or replicated, including the default values of a new form. It then covers the Sections tab, where sections and fields are added, instance-based forms, the Layout tab, and the Workflow tab.

The top menu of the builder contains four areas: Forms, Multi Layout, Stakeholders and Templates. Form creation starts in the Forms area.

Process summary

  1. Open the landing page and choose whether to create a new form or start with an existing one.
  2. To create a new form, enter the Form Name and a unique Form name abbr (Feature ID), then select Create Form. The editor opens with default values already filled in (Step 6). Complete the remaining App Definition fields and keep autoReminder off.
  3. To duplicate a form, select the Tenant Id and OOU Code, tick Duplicate form, enter a new Target Form name abbr, and select List Forms.
  4. Choose the form to replicate from the Forms List.
  5. Review the replicated form in the editor, apply the version naming format to the form name, and save.

For a complete walkthrough of configuring an instance-based form, see Step 12.

Create a new form

Use the Create A New Form panel on the left of the landing page.

  1. Form Name. Type or paste the name of the form, as specified in the requirement.
  2. Form name abbr (Feature ID). Enter a unique abbreviation. Its purpose is to keep each form separate from all other forms. Spaces are not permitted anywhere in it, including between its parts. The naming rules are set out in the next section.
  3. Create Form. Select the button once both fields are complete.
NoteThe Form name abbr is also known as the Feature ID. Two forms must not share the same Feature ID, so it should be treated as a unique identifier.

After Create Form is selected, the editor opens with several fields already filled in. These default values are described in Step 6.

Part 3 of 12

Feature ID naming rules

Standard pattern

The Feature ID is built from three parts:

  1. The initials of the words in the form name.
  2. The university OU code.
  3. The domain.

Permitted characters

Permitted

Capital letters (A to Z), small letters (a to z), numbers (0 to 9) and the underscore ( _ ).

Not permitted

Spaces of any kind, including between the parts of the abbreviation, and all other special characters such as hyphens, dots, slashes, brackets, @, # and &.

Illustration

The following uses made-up values. For a form named "Student Health Immunization Form", with an OU code of 1234 and a domain of xyz, the parts may be joined with underscores as SHIF_1234_xyz. The same value written with spaces, SHIF 1234 xyz, is not valid. An underscore replaces any space.

Character check

Enter a Feature ID below to confirm that it contains only permitted characters. This check does not test uniqueness.

Part 5 of 12

Version naming for duplicated forms

When a new version of an existing form is created, the form name must not be given a prefix or suffix such as "New". Instead, the version month and year are always appended to the end of the form name, in the following format:

<Form Name> Ver.MM.YYYY

ExampleStudent Evaluation of Preceptor Ver.08.2026

Format rules

  • Keep the original form name unchanged, followed by a single space.
  • Write Ver. with a capital V and a full stop.
  • MM is the month as two digits (for example 08 for August).
  • YYYY is the year as four digits (for example 2026).
  • Separate the month and the year with a full stop.
  • Do not add "New" or any other prefix or suffix to the form name.
Form nameStatusReason
Student Evaluation of Preceptor Ver.08.2026CorrectOriginal name followed by Ver.MM.YYYY
New Student Evaluation of PreceptorIncorrect"New" added as a prefix
Student Evaluation of Preceptor NewIncorrect"New" added as a suffix
Student Evaluation of Preceptor Ver.8.2026IncorrectThe month must be two digits (MM)
Student Evaluation of Preceptor Ver 08 2026IncorrectMissing full stops after Ver and between month and year

Choose a form from the Forms List

Selecting List Forms opens the Forms List window over the landing page. The form to be replicated is chosen here.

Window contents

  • A Search forms box at the top, for finding a form by name.
  • A numbered list of the forms available for the selected tenant and OOU Code.
  • An arrow at the end of each row, used to select that form.
  • A close (X) button in the top right corner, to leave without making a selection.

Selecting the form

  1. Locate the form. Scroll the list, or use Search forms.
  2. Verify the title. Read the full title carefully. Some forms have near-identical versions, for example the 12 Week and 16 Week versions of one evaluation tool.

Before selectingConfirm that the Tenant Id, OOU Code and Target Form name abbr are correct on the page behind the window. They determine the source of the copy and the Feature ID of the new form.

Summary: creating a simple new form

The Form tab, which is the first page of the editor, is all that needs to be completed to create a simple new form. The steps are:

  1. On the landing page, enter the Form Name and a unique Form name abbr (Feature ID), then select Create Form.
  2. On the Form tab, confirm the automatic values: Form Name, Form Name Abbreviation, Report Type (Custom), Feature Type (Custom), and Label, Short label, Name and Detail.
  3. Complete Actor Details, Workflow Details and Auto Notification Details according to the requirement.
  4. Select RawData in the App Definition Report Type dropdown.
  5. Select who will fill up the form first in Initiated By.
  6. Make sure autoReminder is off.
  7. Select Save at the top right.
NoteIf multiple responses will be submitted for the form, choose MultipleResponse in Feature Type instead. That process is described in Step 14.

The Sections tab is where the questions of a form are organised. The area is called the Layout Summary. Its heading shows the identifier of the form followed by LayoutSummary, for example Evaluation.Test_abc_123.LayoutSummary. A section is created first, and fields (questions) are then added to it.

Glossary

Every term used in the Form Builder, in one list.

Tenant Id
A unique name for each university. When duplicating a form, the university the form belongs to is selected from this dropdown.
OOU Code
Indicates which domain the form is in. When duplicating, the OOU Code of the domain where the required form is located within the tenant is entered.
Form Name
The name of the form, typed or pasted as specified in the requirement.
Form name abbr (Feature ID)
A unique abbreviation that keeps each form separate from the others. It is built from the initials of the form name, the university OU code and the domain. Only capital letters, small letters, numbers and underscores are permitted, with no spaces.
Duplicate form
A checkbox in the Start With An Existing Form panel. Ticking it makes the Target Form name abbr field appear.
Target Form name abbr
The new Feature ID for a duplicated form. It cannot conflict with the Feature ID of the older form.
List Forms
The button that opens the Forms List for the selected tenant and OOU Code.
Forms List
The window listing the available forms, with a Search forms box and an arrow on each row for selecting the form to replicate.
Report Type
The type of form being created. In the Reports group it is always set to Custom, because custom forms are the ones configured. In the App Definition group it is a dropdown (RawData, Aggregate, SummativeAssessment, Kasa) in which RawData is selected.
Feature Type
A dropdown in the App Definition group with the options Custom, MultipleResponse and Standard. Custom is the type generally created; MultipleResponse is chosen when multiple responses are submitted for the form.
Actor Details
The actors who will fill up the form.
Workflow Details
The workflow of the form, set according to the requirement: which actor fills the form, which signs or reviews it, and which has view access only.
Auto Notification Details
The notifications that are active in the particular form.
Initiated By
A dropdown (Delegate, Student, Admin) used to select who fills up the form first, that is, who starts the form.
autoReminder
An option that must always be kept off. It is ticked by default on a new form and is unticked on every form.
Sections tab (Layout Summary)
The tab where the questions of a form are organised. Its area is called the Layout Summary.
Section
A group created by typing a name in Caption and clicking Add Section. Fields (questions) are added to a section.
Caption
The field in which the name of a new section is typed.
Add Field
The button on a section that opens the field box, which has Main and Advanced sub-tabs.
Description
In the field box, the question that needs to be added.
Meta Information
The sub-information related to the particular question.
Control type
A dropdown that sets the kind of field used for the question. Control types are covered separately.
Property Name
A required entry on the Advanced sub-tab that identifies a question. It must be unique for each and every question.
fieldId
An identifier shown on the Advanced sub-tab. In the example it is the Feature ID of the form followed by the Property Name.
Validation (required)
A rule added with Add Validation. Choosing required makes the question mandatory, and a Message is then chosen to suit the question.
instanceForm
A checkbox on the Form tab, unticked by default. It is ticked when an instance-based form is being created.
Instance-based form
A form configured with instances according to the actors who fill it up, for example Student and Instructor.
Instance Id
The required name of an instance in the Instances list on the Form tab. One instance is added for each actor who fills up the form.
Layout tab
The tab where the layout is prepared so that steps can be added to the workflow.
Summary
An entry on the Layout tab, added with Summary Id and Add Summary. The first summary is added at first, to start adding instance fields.
Edit (summary sections)
A checkbox on each section row in a summary. It sets whether the section is editable on the actor's side. Ticked means editable, unticked means not editable.
Fields (summary sub-tab)
A sub-tab of a summary used to add any field that needs to be excluded from, or shown to, the actor.
FieldsInstances (summary sub-tab)
A sub-tab of a summary where the main part of the instance setup takes place. It starts with "No Instances are added" and an Add Instances button.
Workflow tab
The tab where the steps of the workflow are listed and set up, using the layout prepared on the Layout tab.
MultipleResponse (Feature Type)
The Feature Type chosen when multiple responses will be submitted for the form.
isMultiResponse
An option in App Definition that is ticked for a multi response form. It is unticked by default.
datepicker
A control type used for a date question, such as Date of Initiation.
Label, Short label, Name, Detail
Fields in the App Definition group that are filled automatically with the name of the form when a new form is created.
Version suffix (Ver.MM.YYYY)
The text appended to the end of the form name when a new version of an existing form is created, giving the version month and year. For example: Student Evaluation of Preceptor Ver.08.2026. No "New" prefix or suffix is used.
Replicate
To make a copy of an existing form, which then opens in the editor.
Editor tabs
The tabs across the top of the editor: Form, Sections, Layout, Workflow, Notification and Terms.
Multi-preceptor form
A form that more than one preceptor can fill. All its questions are in one section, the section has Multi Instance ticked, and every summary has the Type RecordSummary.SelectPreceptorSection.
Multi Instance
A checkbox in the section settings, opened with the tick icon on the section row. Ticked for a multi-preceptor form.
RecordSummary.SelectPreceptorSection
The summary Type on the Layout tab that every summary of a multi-preceptor form uses, instead of RecordSummary.Section.
Term
A part of an instance-based form, such as midterm or finalterm, with its own instances. Terms are added on the Terms tab.
Next Term To Switch
On the Terms tab, the Term Id of the term that follows this one. Empty on the last term.
